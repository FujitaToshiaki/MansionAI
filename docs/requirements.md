# 要件定義書

マンション管理AIプラットフォーム

---

## 1. システム概要

### 1.1 目的

本システムは、マンション管理会社が担当物件（マンション）の管理業務を効率化するためのWebプラットフォームである。物件管理を中心機能に据え、議事録・議案・長期修繕計画・規約改訂・管理適正評価・問合せ対応の6機能グループをAIエージェントと連携して提供する。

### 1.2 対象ユーザー

- マンション管理会社の担当者（管理者権限）
- 将来的に管理組合理事への閲覧権限付与を想定（現フェーズは管理者のみ）

### 1.3 技術スタック

| レイヤー | 技術 |
|----------|------|
| フロントエンド | React 18 / TypeScript / Vite / TailwindCSS / shadcn/ui |
| ルーティング | Wouter |
| 状態管理・フェッチ | TanStack Query v5 |
| バックエンド | Express (Node.js / TypeScript) |
| データベース | PostgreSQL（Neon サーバーレス）/ Drizzle ORM |
| AIモデル（OCR） | Gemini 1.5 Flash |
| AIモデル（議事録生成） | Gemini 2.0 Flash |
| AIモデル（音声文字起こし） | OpenAI Whisper-1 |
| ベクトル検索 | テキスト全文検索（将来的にpgvector対応予定） |
| ファイルアップロード | Multer（ディスク / メモリ両モード） |

## 2. 物件管理（中心機能）

### 2.1 マンション一覧

#### 2.1.1 一覧表示

- 登録済みマンションを一覧形式（テーブル）で表示する
- 表示カラム：マンション名・所在地・戸数・管理開始日・法改正対応状況・担当者・最終活動日
- 各行に「詳細」ボタンを配置し、物件詳細画面へ遷移できる

#### 2.1.2 検索

- キーワード検索入力フィールドを提供する
- 法改正対応状況（completed / in_progress / pending / not_required）によるフィルタリングが可能
- 管理開始年によるフィルタリングが可能

#### 2.1.3 ソート

- 管理開始日でのソートを提供する（拡張要件）

#### 2.1.4 ページング

- 多数の物件が存在する場合に備え、ページング機能の実装を想定する（現フェーズでは全件表示）

#### 2.1.5 新規登録

- 「新規登録」ボタンから新しいマンション情報の登録フォームを開く

### 2.2 物件詳細

物件詳細画面（`/condominiums/:id`）は以下の5タブで構成する。

#### 2.2.1 基本情報タブ

- マンション名・住所・戸数・築年数・構造種別・階数
- 管理形態（全部委託 / 一部委託 / 自主管理）
- 月額管理費・月額修繕積立金・積立金残高・滞納率
- 現行規約バージョン・長計バージョン・長計策定日
- 適正評価スコア・適正評価星（1〜5）
- 法改正対応状況・担当者・管理開始日

#### 2.2.2 修繕計画タブ

- 当該物件の長期修繕計画の概要（計画名・期間・総額）を表示
- 長期修繕計画管理機能へのリンクを提供

#### 2.2.3 議案タブ

- 当該物件の議案一覧をプレビュー表示
- 議案管理機能へのリンクを提供

#### 2.2.4 議事録タブ

- 当該物件の議事録一覧をプレビュー表示
- 議事録管理機能へのリンクを提供

#### 2.2.5 評価タブ

- 当該物件の最新適正評価スコアと星を表示
- 管理適正評価機能へのリンクを提供

## 3. 機能グループ別要件

ヘッダーナビゲーションバー（物件選択時に表示）から以下6つの機能グループへアクセスできる。

### 3.1 問合せ管理（AIチャット）

#### 3.1.1 相談チャット

- 管理運営に関する質問を自由文でAIに送信できる
- 選択中の物件に紐付いた文脈でAIが回答する
- チャット形式のUI（送信・受信バブル）で会話履歴を表示する
- 相談カテゴリ（クレーム / 法令解釈 / 運用判断 / 設備 / その他）を選択できる

#### 3.1.2 相談履歴一覧

- 過去の相談ログを一覧表示する
- カテゴリ・ステータス（open / in_progress / resolved / escalated）でフィルタリング可能
- 各相談の詳細（内容・回答・担当者）を閲覧できる

#### 3.1.3 AIによる回答生成

- ユーザーの質問をバックエンドで受け取り、AIエージェント（管理業務相談エージェント）が回答を生成する
- RAGナレッジ検索エージェントと連携し、過去決議・規約を参照した回答を提供する
- 回答は相談ログとして自動保存される

### 3.2 議案管理

#### 3.2.1 議案一覧

- 当該物件の議案をカード形式またはテーブルで一覧表示する
- カテゴリ（規約改訂 / 修繕 / 管理費 / 役員選任 / その他）・ステータス（draft / submitted / decided / archived）でフィルタリング可能
- 通常総会 / 臨時総会の区分を表示する

#### 3.2.2 議案詳細

- 議案のタイトル・カテゴリ・開催日・内容・経緯・結果・採決結果（賛成/反対/棄権）を表示する
- 議案に関連する過去の決議へのリンクを表示する（関連決議リンク）
- 議案のステータスを管理する（draft → submitted → decided → archived）

#### 3.2.3 関連決議リンク

- 議案と過去の決議事項を紐付けてスナップショットとして保存する
- 関連決議の追加・削除が可能
- 関連決議は決議ID・タイトル・開催日・結果・カテゴリ・採決結果を保持する

#### 3.2.4 議案生成（AI支援）

- メモや過去決議を基にAIが議案草稿を生成する機能を提供する

### 3.3 議事録管理

#### 3.3.1 議事録一覧

- 当該物件のRAGナレッジベースに蓄積された議事録を一覧表示する
- 開催日・会議種別（通常総会 / 臨時総会 / 理事会）・出席者数・出席率を表示する
- 各議事録の詳細ページへ遷移できる

#### 3.3.2 議事録詳細

- 議事録の完全な内容（日時・場所・出席者・議題・決定事項・次回予定）を表示する
- RAGナレッジベースから取得した原文テキストを表示する

#### 3.3.3 AI生成（OCRモード）

- 議事録の画像ファイル（複数ページ）をアップロードし、OCRエージェントがテキストを抽出する
- 各ページの抽出精度（0〜100%）と低精度領域（座標付き）を可視化する
- OCR結果を確認・編集後に保存できる
- 対応フォーマット：JPEG / PNG / GIF / WebP（各10MB以内）

#### 3.3.4 AI生成（音声文字起こしモード）

- MP3 / WAV / M4A形式の音声ファイルをアップロードする（25MB以内）
- 音声文字起こしエージェント（OpenAI Whisper）が日本語テキストに変換する
- 変換後のテキストを確認・編集できる

#### 3.3.5 AI生成（テキスト入力モード）

- 会議のメモ（自由テキスト）・会議種別・開催日・場所・出席者を入力する
- 議事録生成エージェント（Gemini 2.0 Flash）が正式な議事録文書を生成する
- 生成結果を確認・コピー・保存できる

### 3.4 長期修繕計画管理

#### 3.4.1 計画ダッシュボード

- 当該物件の長期修繕計画（版数・計画期間・総額・承認日）を一覧表示する
- 修繕項目をカテゴリ（外壁 / 屋根 / 給排水 / EV / 電気 / その他）別に集計して表示する

#### 3.4.2 修繕項目一覧

- 計画内の修繕項目（工事名・カテゴリ・予定年・予定金額・周期・優先度・ステータス）を管理する
- 修繕項目の追加・編集・ステータス変更（planned / completed / deferred / cancelled）が可能

#### 3.4.3 修繕履歴

- 過去の修繕実施記録（工事名・カテゴリ・実施日・金額・施工会社・結果）を参照できる
- 修繕履歴の新規登録が可能

#### 3.4.4 積立金シミュレーション

- 現在の積立金残高と毎月の積立金額を基に将来残高をシミュレーションする
- 修繕項目の予定金額と時期を加味した資金過不足を可視化する
- ガントチャートで修繕スケジュールを表示する

#### 3.4.5 AI見直し分析

- 長期修繕計画の見直し提案をAIが生成する（将来機能）

### 3.5 規約改訂

#### 3.5.1 規約分析

- 現行管理規約・法令・標準管理規約（国交省モデル）の乖離点・課題を分析結果として表示する
- 優先度（high / medium / low）・関連条文・改訂理由・影響度を一覧表示する
- 分析結果は各物件のDBに保存される

#### 3.5.2 AI改訂案生成

- 分析結果の各課題に対して、複数の改訂オプション（決議準拠 / 標準規約準拠 / 独自維持）をAIが生成する
- 現行条文テキストと改訂案テキストを並べて比較表示する
- 採用する改訂案を選択・確定できる

#### 3.5.3 改訂年度管理

- 年度別の改訂ヘッダー（改訂年度・タイトル・ステータス・担当者）を管理する
- ヘッダーに紐付く改訂項目（条文番号・変更前後テキスト・優先度・担当者）を管理する
- ステータス管理：planning → in_progress → completed / cancelled

#### 3.5.4 ウィキ閲覧

- 現行規約の条文をWiki形式で閲覧できる
- RAGナレッジベースに登録された規約文書を参照する

#### 3.5.5 ナレッジベース管理

- RAGシステムに文書（現行規約・議事録・標準管理規約）をアップロードして登録する
- 登録済み文書のチャンク数・アップロード日時を確認できる
- 文書の削除が可能
- キーワードによるナレッジベース検索機能を提供する

### 3.6 管理適正評価

#### 3.6.1 評価チェックリスト

- 管理適正化評価の項目マスタ（カテゴリ：財務 / 修繕 / 管理運営 / 法令 / 居住環境）を参照する
- 各項目にスコア（0〜最大点）と備考を入力する
- 物件を選択してセルフチェックを実施する

#### 3.6.2 スコア集計

- 入力された評価スコアを集計し、合計点・星評価（1〜5）を算出する
- カテゴリ別スコア内訳を表示する
- 改善提案を表示する

#### 3.6.3 評価レポート

- 評価結果を物件詳細の「適正評価スコア」「適正評価星」として保存する
- 評価履歴として一覧表示し、スコア推移を確認できる

## 4. AIエージェント機能要件

### 4.1 OCRエージェント（Gemini 1.5 Flash）

#### 4.1.1 機能概要

- 議事録・各種文書の画像ファイルから日本語テキストを抽出する
- 手書き文字を含む複数ページの画像を処理できる

#### 4.1.2 入力

- 画像バッファ（JPEG / PNG / GIF / WebP）
- MIMEタイプ

#### 4.1.3 出力

- 抽出テキスト全文
- 精度スコア（0〜100）
- 低精度領域リスト（テキスト・信頼度・座標）

#### 4.1.4 精度管理

- 全体精度が低い場合（目安：80%未満）はユーザーへ警告を表示する
- 低精度領域は座標情報付きで画面に可視化する
- 読み取り不能箇所は `[?]` マークで表記する

#### 4.1.5 フォールバック

- Gemini APIエラー時は空テキスト・精度0・空の低精度領域リストを返す
- JSONパースエラー時は正規表現でテキスト部分を抽出して精度85を返す

### 4.2 音声文字起こしエージェント（OpenAI Whisper-1）

#### 4.2.1 機能概要

- 会議の音声録音ファイルを日本語テキストに変換する

#### 4.2.2 入力

- 音声ファイルバッファ（MP3 / WAV / M4A、最大25MB）
- ファイル名・MIMEタイプ

#### 4.2.3 出力

- 文字起こしテキスト（文字列）

#### 4.2.4 フォールバック

- APIキー未設定時はエラーを明示的にスローする
- 変換エラー時は500エラーをクライアントに返す

### 4.3 議事録生成エージェント（Gemini 2.0 Flash）

#### 4.3.1 機能概要

- 会議メモ・文字起こしテキストをもとに正式な議事録を生成する

#### 4.3.2 入力

- 会議種別（通常総会 / 臨時総会 / 理事会 など）
- 開催日
- 開催場所
- 出席者
- 会議メモ（自由テキスト）

#### 4.3.3 出力

- 正式フォーマットの議事録テキスト（マークダウン不使用、プレーンテキスト）

#### 4.3.4 フォールバック

- APIキー未設定時または生成エラー時はテンプレートベースのデモ議事録を返す

### 4.4 決議抽出エージェント

#### 4.4.1 機能概要

- 議事録テキストから決議事項を構造化データとして抽出する

#### 4.4.2 入力

- 議事録テキスト（マークダウンまたはプレーンテキスト）

#### 4.4.3 出力

- 決議一覧（開催日・会議種別・カテゴリ・議題・決議内容・結果・関連条文）

#### 4.4.4 実装方式

- 現フェーズではパターンマッチングによるパース（テーブル形式議事録に対応）
- 将来フェーズでLLMベースの抽出に移行予定

### 4.5 規約分析エージェント

#### 4.5.1 機能概要

- 現行管理規約・法令・標準管理規約（国交省モデル）の比較分析を実施する
- 乖離点・課題を優先度付きで一覧化する

#### 4.5.2 入力

- 物件ID（分析対象の特定）
- 分析設定（scope など）

#### 4.5.3 出力

- 分析結果一覧（優先度・対象条文・タイトル・理由・現行テキスト・改訂案テキスト・根拠・影響度）

#### 4.5.4 フォールバック

- 分析タスクはAIタスクキュー（ai_tasks）に登録してステータス管理する
- エラー時は ai_tasks.status を 'failed' に更新する

### 4.6 規約改訂案生成エージェント

#### 4.6.1 機能概要

- 規約分析結果の各課題に対して複数の改訂オプションを生成する

#### 4.6.2 改訂オプション種別

| オプション | 説明 |
|------------|------|
| 決議準拠 | 過去の決議事項に基づく改訂 |
| 標準規約準拠 | 国交省標準管理規約に準拠した改訂 |
| 独自維持 | 現行の独自ルールを維持した改訂 |

#### 4.6.3 フォールバック

- APIエラー時は空の改訂案リストを返す

### 4.7 RAGナレッジ検索エージェント

#### 4.7.1 機能概要

- テキスト全文検索（ILIKE）により、ナレッジベースから関連するチャンクを取得する
- 取得したチャンクをコンテキストとしてAI回答生成に利用する

#### 4.7.2 入力

- 検索クエリ文字列
- 物件ID（スコープ限定）
- ドキュメントタイプ（省略可、省略時は全タイプ対象）

#### 4.7.3 出力

- 関連チャンク一覧（チャンクID・内容・ドキュメントID・インデックス）
- 関連ドキュメント一覧

#### 4.7.4 チャンキング仕様

- チャンクサイズ：2,000文字
- オーバーラップ：400文字
- エンベディング：将来的にpgvectorによるベクトル検索に移行予定

### 4.8 管理業務相談エージェント（チャット型）

#### 4.8.1 機能概要

- 管理運営上の質問に対して対話型で回答する
- RAGナレッジベースの内容を参照して文脈に沿った回答を生成する

#### 4.8.2 入力

- ユーザーの質問文字列
- 相談カテゴリ
- 物件ID

#### 4.8.3 出力

- AI生成の回答テキスト
- 参照した知識ベースの情報

#### 4.8.4 フォールバック

- APIエラー時はエラーメッセージを表示し、手動回答入力への誘導を行う

## 5. 非機能要件

### 5.1 パフォーマンス

- 一覧系APIのレスポンスタイム：p95で2秒以内
- OCR処理（1ページ）：30秒以内
- 音声文字起こし（10分音声）：60秒以内
- 議事録生成：30秒以内

### 5.2 セキュリティ

- APIキー（GEMINI_API_KEY / OPENAI_API_KEY）は環境変数で管理し、フロントエンドに露出させない
- ファイルアップロードはサイズ制限（画像10MB / 音声25MB）を適用する
- ファイル種別チェック（MIMEタイプ検証）を実施する
- SQLインジェクション対策はパラメータバインド（`$1, $2`）で対応する

### 5.3 データ保持

- ナレッジベースの文書・チャンクはPostgreSQLに永続化する
- OCR処理後の画像ファイルは `uploads/` ディレクトリにディスク保存する
- 音声ファイルは文字起こし完了後に削除する
- 相談ログ・評価チェック・修繕履歴は物件に紐付けてDBに永続化する

### 5.4 可用性

- 開発環境：Node.js / Vite による Hot Module Replacement
- 本番環境：Replit Deploymentによるクラウドホスティング
